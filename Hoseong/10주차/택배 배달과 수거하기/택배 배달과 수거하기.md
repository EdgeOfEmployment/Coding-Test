# [2023 KAKAO BLIND RECRUITMENT] 택배 배달과 수거하기

## 1. 문제 개요 및 분석

* **출처:** 2023 KAKAO BLIND RECRUITMENT
* **난이도:** Level 2
* **주요 알고리즘:** 그리디(Greedy), 누적합/역방향 탐색(Accumulation)

### 문제 핵심
1. 일렬로 연결된 $N$개의 집에 대해 택배 배달 및 빈 상자 수거를 수행해야 합니다.
2. 트럭에는 최대 $cap$개의 상자를 실을 수 있습니다.
3. 물류창고(거리 0)에서 출발하여 가장 멀리 있는 요구 사항부터 해결하고 돌아오는 것이 이동 거리를 최소화하는 핵심입니다.
4. 모든 배달과 수거를 마치는 **최소 이동 거리**를 구해야 합니다.

### 제약사항
* $1 \le cap \le 50$
* $1 \le n \le 100,000$
* $0 \le deliveries[i], pickups[i] \le 50$
* 정답 거리가 `int` 범위를 초과할 수 있으므로 `long long` 타입을 사용해야 합니다.

---

## 2. 기존 코드 분석 및 병목 원인

### 기존 코드의 접근 방식
* 가장 멀리 있는 미완료 집(`idx`)을 찾습니다.
* 해당 집까지 왕복 거리(`(idx + 1) * 2`)를 더합니다.
* `while` 문을 통해 `idx`부터 역방향으로 물류량을 직접 차감(`deliveries[i] -= use_d`, `pickups[i] -= use_p`)합니다.

### 병목 현상 발생 이유 ($O(N^2)$ 최악 시간 복잡도)
* **원인:** 트럭이 한 번 왕복할 때마다 이중 `while` 루프를 돌며 배열 원소를 일일이 갱신합니다.
* **최악의 상황:** 각 집의 배달/수거량이 매우 작고(예: 1개), $N = 100,000$이며 $cap$이 큰 경우, 방문 횟수마다 $N$번의 원소를 지속적으로 중복 탐색하게 되어 **시간 복잡도가 $O(N^2)$**에 가깝게 증가합니다.
* **결과:** 채점 결과 정확성은 100점이지만, 테스트 17번(8.53초), 19번(1.46초), 20번(1.77초)에서 실행 시간이 과도하게 발생합니다.

## 3. $O(N)$ 최적화 알고리즘 설계

### 핵심 아이디어: 역방향 누적 탐색 (Greedy Accumulation)
1. **가장 먼 집부터 탐색:** 가장 멀리 있는 집에 배달/수거할 물품이 남아있다면 어차피 해당 위치까지 트럭이 가야 합니다. 따라서 $N-1$번째 집부터 $0$번째 집까지 역순으로 조사합니다.
2. **여유 용량 누적 관리 (`d_cap`, `p_cap`):**
   * 트럭이 방문할 때 가져갈 수 있는 용량을 미리 계산합니다.
   * `d_cap -= deliveries[i]`, `p_cap -= pickups[i]`로 현재 집의 물량을 반영합니다.
3. **왕복 횟수 계산:**
   * `d_cap < 0` 또는 `p_cap < 0`이 되는 순간, 해당 집까지 트럭을 보내야 함을 의미합니다.
   * 부족한 물량 중 더 많은 쪽을 기준으로 필요한 왕복 횟수 `cnt`를 계산합니다:
     $$\text{cnt} = \max\left(\left\lceil \frac{-d\_cap}{cap} \right\rceil, \left\lceil \frac{-p\_cap}{cap} \right\rceil\right)$$
   * 정수 연산으로는 `(-d_cap + cap - 1) / cap` 형태를 활용할 수 있습니다.
4. **거리 및 용량 업데이트:**
   * 이동 거리 추가: `answer += (i + 1) * 2 * cnt`
   * 용량 충전: `d_cap += cnt * cap`, `p_cap += cnt * cap`
   * 이렇게 충전된 용량은 이전 집들($i-1, i-2, \dots$)의 배달/수거에 자연스럽게 이월되어 사용됩니다.

## 4. C++ 최적화 소스 코드

```cpp
#include <vector>
#include <algorithm>

using namespace std;

long long solution(int cap, int n, vector<int> deliveries, vector<int> pickups) {
    long long answer = 0;
    
    // 트럭의 누적 배달/수거 여유 용량 (음수일 경우 추가 왕복 필요)
    long long d_cap = 0;
    long long p_cap = 0;

    // 가장 멀리 있는 집부터 역순으로 탐색
    for (int i = n - 1; i >= 0; --i) {
        d_cap -= deliveries[i];
        p_cap -= pickups[i];

        // 배달 또는 수거 수량이 부족한 경우 (왕복 필요)
        if (d_cap < 0 || p_cap < 0) {
            // 부족한 분량을 채우기 위한 최소 왕복 횟수 계산
            long long needed_d = (d_cap < 0) ? (-d_cap + cap - 1) / cap : 0;
            long long needed_p = (p_cap < 0) ? (-p_cap + cap - 1) / cap : 0;
            long long cnt = max(needed_d, needed_p);

            // 왕복 거리 누적 (물류창고 <-> (i+1)번째 집)
            answer += (long long)(i + 1) * 2 * cnt;

            // 트럭 방문 횟수만큼 용량 충전
            d_cap += cnt * cap;
            p_cap += cnt * cap;
        }
    }

    return answer;
}
```

## 5. Python 참고 코드

```python
def solution(cap, n, deliveries, pickups):
    answer = 0
    d_cap = 0
    p_cap = 0
    
    for i in range(n - 1, -1, -1):
        d_cap -= deliveries[i]
        p_cap -= pickups[i]
        
        if d_cap < 0 or p_cap < 0:
            needed_d = (-d_cap + cap - 1) // cap if d_cap < 0 else 0
            needed_p = (-p_cap + cap - 1) // cap if p_cap < 0 else 0
            cnt = max(needed_d, needed_p)
            
            answer += (i + 1) * 2 * cnt
            
            d_cap += cnt * cap
            p_cap += cnt * cap
            
    return answer
```
