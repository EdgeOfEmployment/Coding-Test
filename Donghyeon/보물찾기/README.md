<p>격자의 각 열은 굴착 가능한 최대 깊이가 각각 다를 수 있습니다. 굴착 로봇이 <code>col</code>열을 파도록 명령을 보내면 가능한 최대 깊이만큼 땅을 판 뒤 돌아옵니다. 만약 <code>col</code>열에 보물이 있었다면 보물을 가지고 돌아오며, 보물이 없었더라도 <code>col</code>열을 기준으로 왼쪽 방향에 보물이 있는지 오른쪽 방향에 보물이 있는지에 대한 정보를 가지고 돌아옵니다. 이때 땅을 팔 때마다 굴착 가능한 깊이만큼 비용이 발생합니다.</p>

## 풀이

### 문제 유형 파악

이 문제는 인터랙티브 형태의 이분 탐색처럼 보이지만, 각 열마다 굴착 비용(`depth[i]`)이 다르고 **최악의 경우에도 총비용이 `money`를 넘으면 안 된다**는 조건이 핵심이다. 단순히 "중간 열을 파고 결과에 따라 반씩 줄여나가는" 이분 탐색으로는 최악의 비용을 보장할 수 없다.

### 처음 시도와 실패 이유 (주석 처리된 코드)

처음에는 일반적인 이분 탐색처럼 `[start, fin]` 구간의 중앙값 `mid`를 계속 파는 방식으로 접근했다.

```js
let mid = Math.floor((fin + start) / 2);
// res(-1, 0, 1)에 따라 구간을 반씩 좁혀가며 mid를 다시 계산
```

하지만 이 방식은 `depth`가 큰 열이 구간 중앙에 걸리는 경우를 전혀 고려하지 않는다. 예를 들어 중앙값 열의 `depth`가 매우 크면, 단 한 번의 굴착만으로도 `money`를 초과할 수 있다. 즉 "구간을 절반으로 줄이는 것"과 "비용을 최소화하는 것"은 서로 다른 목표이며, 열의 위치가 아니라 **굴착 비용을 고려해서 어떤 열을 먼저 팔지 결정**해야 한다는 것을 깨닫고 접근을 바꿨다.

### 최종 접근: 구간 DP로 최적 굴착 순서를 미리 계산

이 문제는 사실 "가중치가 있는 노드들을 대상으로, 최악의 경우 탐색 비용을 최소화하는 이진 탐색 트리를 만드는 문제"와 같은 구조다. 흔히 알려진 Optimal Binary Search Tree가 기댓값(가중 평균 비용)을 최소화하는 것과 달리, 여기서는 **최악의 경우(최댓값)**를 최소화한다는 점만 다르다.

- `dp[L][R]`: 보물이 구간 `[L, R]` 안 어딘가에 있다고 가정했을 때, 100% 확률로 찾아내기 위해 필요한 **최소의 "최악 비용"**
- `bestK[L][R]`: 구간 `[L, R]`에서 그 최소 비용을 달성하기 위해 가장 먼저 파야 하는 열

구간 `[L, R]`에서 `k`열을 먼저 판다고 하면,

- `k`를 파는 비용 `depth[k-1]`은 항상 발생하고,
- 그 결과 보물이 왼쪽 `[L, k-1]`에 있을 수도, 오른쪽 `[k+1, R]`에 있을 수도 있는데, **어느 쪽이 나오더라도 100% 찾아낼 수 있어야 하므로** 이후 비용은 두 하위 구간의 `dp` 값 중 더 큰 쪽(최악의 경우)을 따라야 한다.

따라서 점화식은 다음과 같다.

```
dp[L][R] = min_{k=L..R} ( depth[k-1] + max(dp[L][k-1], dp[k+1][R]) )
```

빈 구간(`L > R`)은 `dp = 0`으로 초기화되어 있어 재귀의 기저 조건이 자연스럽게 처리된다. 구간의 길이(`len`)를 1부터 `n`까지 늘려가며 바텀업으로 채우면, 모든 `[L, R]`과 그때의 최적 시작열 `k`를 `O(n³)`에 계산할 수 있다. `n ≤ 200`이므로 최대 약 `8 × 10⁶`번의 연산이라 시간 안에 충분히 계산된다.

### 실제 굴착 시뮬레이션

DP 테이블 계산이 끝나면, 실제로는 `excavate`를 호출해가며 결과를 확인해야 한다. `L = 1, R = n`에서 시작해 `bestK[L][R]`이 알려주는 열을 파고,

- 결과가 `0`이면 그 열이 보물의 위치이므로 바로 반환
- 결과가 `-1`이면 보물이 더 왼쪽에 있다는 뜻이므로 `R = target - 1`로 구간을 좁히고
- 결과가 `1`이면 더 오른쪽에 있다는 뜻이므로 `L = target + 1`로 좁힌다

이 과정을 반복하면 항상 DP로 미리 계산해 둔 "최악의 경우 최소 비용" 전략을 그대로 따라가게 되므로, 실제 보물의 위치가 어디든 총비용이 `dp[1][n]`(문제에서 보장하는 최소 비용) 이내로 유지된다.
