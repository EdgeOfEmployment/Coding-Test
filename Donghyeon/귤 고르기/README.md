### 문제 설명

<p>경화는 과수원에서 귤을 수확했습니다. 경화는 수확한 귤 중 'k'개를 골라 상자 하나에 담아 판매하려고 합니다. 그런데 수확한 귤의 크기가 일정하지 않아 보기에 좋지 않다고 생각한 경화는 귤을 크기별로 분류했을 때 서로 다른 종류의 수를 최소화하고 싶습니다.</p>

<p>예를 들어, 경화가 수확한 귤 8개의 크기가 [1, 3, 2, 5, 4, 5, 2, 3] 이라고 합시다. 경화가 귤 6개를 판매하고 싶다면, 크기가 1, 4인 귤을 제외한 여섯 개의 귤을 상자에 담으면, 귤의 크기의 종류가 2, 3, 5로 총 3가지가 되며 이때가 서로 다른 종류가 최소일 때입니다.</p>

<p>경화가 한 상자에 담으려는 귤의 개수 <code>k</code>와 귤의 크기를 담은 배열 <code>tangerine</code>이 매개변수로 주어집니다. 경화가 귤 k개를 고를 때 크기가 서로 다른 종류의 수의 최솟값을 return 하도록 solution 함수를 작성해주세요.</p>

## 풀이와 생각

### 접근 방법

- 그리디(Greedy) + 해시맵(Map)을 이용한 빈도수 집계
- "서로 다른 크기의 종류 수를 최소화"하려면, 개수가 많은 크기부터 우선적으로 채워야 종류 수를 아낄 수 있다는 것이 핵심 아이디어
- Map으로 각 크기별 개수를 센 뒤, 개수를 내림차순 정렬하고, 가장 개수가 많은 크기부터 k개를 채울 때까지 순서대로 소비
- k개를 채우는 데 사용된 크기(종류)의 개수가 곧 정답

### 왜 그리디가 성립하는가

- 어떤 "크기 값"을 고르느냐는 중요하지 않고, k개를 채우기 위해 몇 가지 종류가 필요한지만 중요함
- 종류 수를 최소화하려면 한 종류당 최대한 많은 개수를 소비하는 것이 항상 유리하므로, 개수가 큰 순서대로 소비하는 것이 최적
- 교환 논증(exchange argument)으로 보면, 적게 있는 종류를 먼저 썼다고 가정해도 많이 있는 종류로 바꿔 써도 손해가 없으므로 내림차순 소비가 항상 최적해를 보장

### 복잡도

- 빈도수 집계 O(n), 정렬 O(n log n) → 전체 O(n log n)

### 느낀 점

- "종류의 최솟값"이라는 조건을 보자마자 개수 기준 정렬 그리디를 떠올릴 수 있어야 하는 문제
- Map을 이용한 빈도수 집계 → 정렬 → 그리디 소비 패턴은 이후 비슷한 유형(종류 최소화/최대화) 문제에서도 반복적으로 쓰일 것 같음
