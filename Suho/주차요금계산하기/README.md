# 주차 요금 계산

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/92341
- 사용 알고리즘/자료구조: 구현, 해시맵(`dict`), 정렬

## 1. 문제 이해

차량별 입·출차 기록을 바탕으로 누적 주차 시간을 계산한 뒤, 요금표에 따라 차량별 주차 요금을 구하는 문제다.

- 같은 차량이 하루 동안 여러 번 입·출차할 수 있으므로 주차 시간을 누적해야 한다.
- 입차 기록만 있고 출차 기록이 없다면 `23:59`에 출차한 것으로 처리한다.
- 기본 시간을 초과한 시간은 단위 시간으로 나누고 올림하여 요금을 계산한다.
- 결과는 차량 번호가 작은 순서대로 반환해야 한다.
- `records`의 길이는 최대 1,000이므로 `O(n log n)` 풀이로 충분하다.

## 2. 처음 접근한 방식

처음에는 차량 번호를 key로 사용하는 딕셔너리를 떠올렸다.

다만 하나의 차량에 대해 입차 시간과 누적 주차 시간이 모두 필요했기 때문에, 딕셔너리의 value를 어떻게 구성해야 할지 막혔다. 고민 끝에 역할이 다른 정보를 다음 두 딕셔너리로 분리했다.

- `in_time`: 현재 주차 중인 차량의 입차 시간
- `total_time`: 차량별 누적 주차 시간

처리 순서는 다음과 같이 정리했다.

1. 문자열 시간을 분 단위 정수로 변환한다.
2. `IN`이면 차량의 입차 시간을 저장한다.
3. `OUT`이면 출차 시간에서 저장된 입차 시간을 빼고 누적한다.
4. 모든 기록을 처리한 뒤 아직 출차하지 않은 차량은 `23:59`에 출차한 것으로 계산한다.
5. 차량 번호를 정렬하고 누적 시간에 따른 요금을 계산한다.

## 3. 최종 풀이

```python
import math
def solution(fees, records):

    in_time = {}  # 차량번호: 입차 시간
    total_time = {} # 차량번호: 누적 주차 시간
    answer = []
    # 차량 기준으로 다시 정렬.
    # out에서 가장 최근의 in시간을 빼야함.
    for record in records:
        time,car_num,history = record.split()
        #시간 -> 분으로 바꾸기
        hour, minute = map(int, time.split(":"))
        time_min = hour * 60 + minute

        if history == "IN":
            # 입차 시간 저장
            in_time[car_num] =time_min

        else:
            # 주차 시간 계산
            park_t = time_min-in_time[car_num]
            # total_time에 누적
            total_time[car_num] = total_time.get(car_num, 0) + park_t
            # in_time에서 해당 차량 제거
            del in_time[car_num]
    # in_time에 남아 있는 미출차 차량 처리
    # 만약 출차 되지 않았다면, 23:59에서 입차한 시간을 빼야함.
    if in_time:
        for car_num in in_time:
            park_t = 23*60+59-in_time[car_num]
            total_time[car_num] = total_time.get(car_num, 0) + park_t

    answer = []

    # 차량별 요금 계산
    #올림함수
    #math.ceil(숫자)
    # 기본 시간 180분(fees[0]) 보다 작으면 5000원(fees[1])
    #180분 보다 크면 5000원 + math.ceil((누적주차시간-180)/10 =(fees[2])) * 600 =(fees[3])
    for car_num in sorted(total_time):
        v = total_time[car_num]
        if fees[0]>=v:
            total_fee = fees[1]
        else:
            total_fee = fees[1] +  math.ceil((v-fees[0])/fees[2]) * fees[3]
        # answer에 추가
        answer.append(total_fee)

    return answer
```

### 막힌 부분 및 시행착오

#### 1) 차량별 정보를 어떻게 저장할지

처음부터 차량 번호를 key로 하는 딕셔너리는 떠올렸지만, 입차 시간과 누적 시간을 하나의 딕셔너리에서 어떻게 구분할지 막혔다.

두 정보는 사용 목적이 다르다.

- 입차 시간은 다음 `OUT` 기록을 처리할 때까지만 필요하다.
- 누적 시간은 모든 입·출차 기록을 처리한 후 요금을 계산할 때 필요하다.

따라서 `in_time`과 `total_time`으로 분리하면 각 딕셔너리의 역할이 명확해진다. 출차 시 `pop()`을 사용하면 입차 시간을 얻는 동시에 현재 주차 중인 차량 목록에서도 제거할 수 있다.

#### 2) 출차 기록이 없는 차량 처리

기록을 모두 처리한 후에도 `in_time`에 남은 차량은 출차 기록이 없는 차량이다. 이 차량들은 문제 조건에 따라 `23:59`에 출차한 것으로 계산해 `total_time`에 더한다.

#### 3) 올림 함수 검색

요금 계산에 올림이 필요하다는 점은 알고 있었지만 함수 이름이 기억나지 않아 `math.ceil()`을 검색했다.

### 시간복잡도 및 공간복잡도

`records`의 개수를 `n`, 차량의 수를 `k`라고 하자.

| 처리                    |   시간복잡도 | 이유                       |
| ----------------------- | -----------: | -------------------------- |
| 전체 기록 순회          |  평균 `O(n)` | 각 기록을 한 번씩 처리     |
| 딕셔너리 조회·추가·삭제 |  평균 `O(1)` | 해시 기반 연산             |
| 미출차 차량 처리        |       `O(k)` | 남은 차량을 한 번씩 처리   |
| 차량 번호 정렬          | `O(k log k)` | 차량 번호 순서로 결과 생성 |
| 요금 계산               |       `O(k)` | 차량마다 한 번 계산        |

따라서 전체 시간복잡도는 다음과 같다.

O(n + k \log k)

차량 수는 기록 수보다 많을 수 없으므로 최악의 경우 `O(n log n)`으로 표현할 수 있다. 차량별 입차 시간과 누적 시간을 저장하므로 공간복잡도는 `O(k)`, 최악의 경우 `O(n)`이다.

## 4. 최종 정리

- 여러 기록을 같은 대상별로 묶어야 할 때는 대상의 식별자인 차량 번호를 딕셔너리 key로 사용할 수 있다.
- 성격과 생명주기가 다른 정보는 `in_time`과 `total_time`처럼 자료구조를 분리하면 관리하기 쉽다.
- 시간은 분 단위 정수로 변환하면 차이를 간단하게 계산할 수 있다.
- `dict.pop(key)`은 값을 가져오는 동시에 해당 key를 삭제한다.
- 정렬 때문에 전체 시간복잡도는 `O(n + k log k)`, 최악의 경우 `O(n log n)`이다.
- 입력 조건을 확인한 뒤 반복문뿐 아니라 정렬과 내부 연산의 비용까지 함께 계산해야 한다.

### AI 활용

- 차량 번호를 key로 하는 딕셔너리를 사용하는 방향은 직접 떠올렸지만, 입차 시간과 누적 주차 시간을 어떤 변수로 나눠 관리해야 할지 막혔다.
- 이 과정에서 `in_time`과 `total_time`이라는 두 딕셔너리로 분리하는 방법을 도움받았다.
- 문제에 주어진 입력 조건이 시간복잡도와 어떤 관계가 있는지 설명을 도움받았다.
