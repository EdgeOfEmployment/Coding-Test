## 2️⃣ 코드

---

### 1차 풀이

```python
def solution(n):
    # 가로 길이만 고려하면 1과 2의 합으로 생각할 수 있다.
    # n = 1: 1
    # n = 2: 1+1, 2
    # n = 3: 1+2, 2+1, 1+1+1
    # n = 4: 2+2, 1+1+2, 2+1+1, 1+2+1, 1+1+1+1

    dp = [0] * n
    dp[0] = 1
    dp[1] = 2

    for i in range(2, n):
        dp[i] = dp[i-1] + dp[i-2]

    return dp[-1] % 1_000_000_007
```

### 최종 풀이

```python
def solution(n):
    if n == 1:
        return 1

    MOD = 1_000_000_007

    dp = [0] * n
    dp[0] = 1
    dp[1] = 2

    for i in range(2, n):
        dp[i] = (dp[i-1] + dp[i-2]) % MOD

    return dp[-1]
```

## 3️⃣ 문제 풀이 아이디어

---

### 처음 생각한 과정

이 문제는 세로 길이가 항상 2로 고정되어 있으므로, 타일이 차지하는 가로 길이만 고려했다.

- 세로 타일 1개를 놓으면 가로 길이 `1`을 채운다.
- 가로 타일은 위아래로 2개를 놓아야 하므로 가로 길이 `2`를 채운다.

따라서 이 문제는 숫자 `1`과 `2`를 사용해 합이 `n`이 되는 모든 순서를 구하는 문제로 바꿔 생각할 수 있다.

```text
n = 1
1
→ 1가지

n = 2
1 + 1
2
→ 2가지

n = 3
1 + 2
2 + 1
1 + 1 + 1
→ 3가지

n = 4
2 + 2
1 + 1 + 2
2 + 1 + 1
1 + 2 + 1
1 + 1 + 1 + 1
→ 5가지
```

`1 + 2`와 `2 + 1`은 합은 같지만 타일을 놓는 순서가 다르므로 서로 다른 방법이다.

### 점화식 구하기

가로 길이가 `n`인 바닥을 채우는 방법을 마지막에 놓은 타일을 기준으로 나누었다.

#### 마지막에 세로 타일을 놓은 경우

세로 타일은 가로 길이 `1`을 차지한다.

따라서 앞의 `n-1` 길이를 채운 모든 방법 뒤에 세로 타일을 추가할 수 있다.

```text
경우의 수 = dp[n-1]
```

#### 마지막에 가로 타일 2개를 놓은 경우

가로 타일 2개는 가로 길이 `2`를 차지한다.

따라서 앞의 `n-2` 길이를 채운 모든 방법 뒤에 가로 타일 2개를 추가할 수 있다.

```text
경우의 수 = dp[n-2]
```

두 경우를 더하면 다음과 같은 점화식이 나온다.

```text
dp[n] = dp[n-1] + dp[n-2]
```

피보나치 수열과 숫자가 우연히 비슷해서 사용한 것이 아니다. 마지막에 놓을 수 있는 타일이 가로 길이 `1`을 차지하는 경우와 `2`를 차지하는 경우로 나뉘기 때문에 피보나치 형태의 점화식이 만들어진다.

## 4️⃣ 첫 번째 풀이의 실패 원인

---

첫 번째 풀이에서는 반복문이 끝난 후 최종 결과에만 나머지 연산을 적용했다.

```python
return dp[-1] % 1_000_000_007
```

마지막에만 나머지를 구해도 수학적인 결과는 같다. 하지만 계산 과정에서 DP 값이 계속 커진다는 문제가 있다.

예를 들어 나누는 수가 `10`이라고 가정하면 다음 두 계산의 결과는 같다.

```text
마지막에 나누는 경우

27 + 38 = 65
65 % 10 = 5
```

```text
계산할 때마다 나누는 경우

27 % 10 = 7
38 % 10 = 8

(7 + 8) % 10 = 5
```

즉, 중간에 나머지를 구해도 최종 나머지는 변하지 않는다.

```text
(a + b) % M
= ((a % M) + (b % M)) % M
```

`n`이 커지면 피보나치 수의 자릿수도 계속 증가한다. Python은 매우 큰 정수도 저장할 수 있지만, 숫자의 자릿수가 많아질수록 덧셈에 필요한 시간과 메모리도 증가한다.

따라서 마지막에 한 번만 나누면 반복문을 수행하는 동안 큰 숫자를 계속 계산하게 되어 효율성 테스트에서 시간 초과가 발생할 수 있다.

반면 매번 나머지를 구하면 `dp[i]`에 저장되는 값이 항상 `1,000,000,007`보다 작게 유지된다.

```python
dp[i] = (dp[i-1] + dp[i-2]) % 1_000_000_007
```

결과는 동일하지만 계산에 사용되는 숫자의 크기가 작아지기 때문에 더 효율적이다.

## 5️⃣ 처음에 생각하지 못했던 부분

---

처음에는 문제에서 나머지를 반환하라고 했기 때문에 최종 결과에만 `% 1_000_000_007`을 적용하면 된다고 생각했다.

하지만 이 문제에서는 최종 결과뿐만 아니라, 계산 과정에서 만들어지는 숫자의 크기도 고려해야 했다.

나머지 연산을 매번 적용해도 최종 결과는 바뀌지 않는다. 따라서 DP 값을 계산할 때마다 나머지를 구해 중간 값이 지나치게 커지지 않도록 해야 한다.

## 6️⃣ 시간복잡도와 공간복잡도

---

### 시간복잡도

```text
O(n)
```

`2`부터 `n-1`까지 반복문을 한 번 실행한다.

### 공간복잡도

```text
O(n)
```

길이가 `n`인 DP 배열을 사용한다.

## 7️⃣ 추가로 개선할 수 있는 부분

---

현재 값을 구할 때 필요한 것은 이전 두 값뿐이다.

따라서 모든 값을 DP 배열에 저장하지 않고 변수 2개만 사용하면 공간복잡도를 `O(1)`로 줄일 수 있다.

```python
def solution(n):
    if n == 1:
        return 1

    MOD = 1_000_000_007

    prev2 = 1
    prev1 = 2

    for _ in range(2, n):
        current = (prev1 + prev2) % MOD
        prev2 = prev1
        prev1 = current

    return prev1
```

- 시간복잡도: `O(n)`
- 공간복잡도: `O(1)`
