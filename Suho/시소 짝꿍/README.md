# 시소 짝꿍

## 1️⃣ 문제 링크

[프로그래머스 - 시소 짝꿍](https://school.programmers.co.kr/learn/courses/30/lessons/152996)

시소에는 중심으로부터 2m, 3m, 4m 떨어진 좌석이 있다. 두 사람의 몸무게와 좌석까지의 거리를 곱한 값이 같아 시소가 평형을 이루는 경우, 두 사람을 시소 짝꿍이라고 한다.

사람들의 몸무게가 담긴 `weights`가 주어질 때, 시소 짝꿍이 될 수 있는 쌍의 개수를 구하는 문제이다.

---

## 2️⃣ 첫 번째 풀이

```python
def solution(weights):
    answer = 0

    # 작은 몸무게 / 큰 몸무게가
    # 1, 2/3, 3/4, 1/2 중 하나이면 짝꿍이다.
    v = [1, 2/3, 3/4, 1/2]

    for i in range(len(weights)):
        for j in range(i + 1, len(weights)):
            max_num = max(weights[i], weights[j])
            min_num = min(weights[i], weights[j])

            if min_num / max_num in v:
                answer += 1

    return answer
```

### 첫 번째 풀이 아이디어

처음에는 두 사람의 몸무게를 직접 비교하는 완전탐색을 생각했다.

두 몸무게 중 큰 값을 `max_num`, 작은 값을 `min_num`으로 두고 다음 비율 중 하나를 만족하면 시소 짝꿍이라고 판단했다.

```text
1, 2/3, 3/4, 1/2
```

예를 들어 몸무게가 270과 360이라면 다음과 같다.

```text
270 / 360 = 3/4
```

따라서 두 사람은 각각 4m와 3m 위치에 앉으면 균형을 이룰 수 있다.

문제의 조건에서 `weights`의 길이가 최대 \(10^5\)이기 때문에 이중 반복문을 사용해도 되는지 의문이 들었다. 하지만 모든 쌍을 직접 비교하는 방법 외에는 떠오르지 않아 그대로 구현했고, 예상대로 시간 초과가 발생했다.

### 시간 초과가 발생한 이유

사람이 \(N\)명이라면 비교해야 하는 쌍의 수는 다음과 같다.

$$
\frac{N(N-1)}{2}
$$

따라서 첫 번째 풀이의 시간복잡도는 다음과 같다.

$$
O(N^2)
$$

`weights`의 길이가 100,000이라면 최악의 경우 약 50억 쌍을 비교해야 하므로 시간 내에 처리하기 어렵다.

## 3️⃣ 떠올리지 못했던 부분

처음에는 현재 사람과 나머지 모든 사람을 직접 비교해야 한다고 생각했다.

하지만 이 문제에서는 현재 몸무게와 짝이 될 수 있는 몸무게가 다음 네 가지로 정해져 있다.

현재 몸무게가 `weight`이고, 오름차순으로 정렬된 배열에서 이전에 나온 더 작거나 같은 몸무게만 확인한다면 후보는 다음과 같다.

```text
weight
weight × 2/3
weight × 3/4
weight × 1/2
```

예를 들어 현재 몸무게가 360이라면 확인해야 하는 몸무게는 다음 네 개뿐이다.

```text
360, 240, 270, 180
```

따라서 현재 사람과 앞의 모든 사람을 하나씩 비교할 필요가 없다. 이전에 나온 몸무게별 인원수를 딕셔너리에 저장하면, 각 후보가 몇 번 등장했는지를 바로 확인할 수 있다.

핵심은 다음과 같다.

1. `weights`를 오름차순으로 정렬한다.
2. 딕셔너리에 이전까지 등장한 몸무게별 인원수를 저장한다.
3. 현재 몸무게와 짝이 될 수 있는 네 가지 후보를 계산한다.
4. 각 후보가 이전에 몇 번 등장했는지 확인해 `answer`에 더한다.
5. 모든 후보를 확인한 후 현재 몸무게를 딕셔너리에 등록한다.

현재 몸무게를 후보 확인 이후에 등록해야 자기 자신을 짝으로 세지 않는다.

---

## 4️⃣ 개선한 풀이

```python
def solution(weights):
    answer = 0

    # 현재 몸무게보다 작거나 같은 짝꿍 후보의 비율
    v = [1, 2/3, 3/4, 1/2]

    weights.sort()

    # 이전까지 등장한 몸무게별 인원수
    count = {}

    for i in range(len(weights)):
        candidates = []

        # 현재 몸무게와 짝이 될 수 있는 후보 계산
        for j in range(4):
            candidates.append(weights[i] * v[j])

        # 이전에 나온 후보의 인원수만큼 쌍 추가
        for candidate in candidates:
            answer += count.get(candidate, 0)

        # 현재 사람을 딕셔너리에 등록
        count[weights[i]] = count.get(weights[i], 0) + 1

    return answer
```

### `count`의 역할

`count`는 현재 위치보다 앞에서 등장한 몸무게별 인원수를 저장한다.

예를 들어 다음과 같다면:

```python
count = {
    100: 2,
    180: 1,
    270: 1
}
```

앞에서 몸무게 100인 사람이 2명, 180인 사람이 1명, 270인 사람이 1명 나왔다는 뜻이다.

현재 몸무게가 360이라면 후보는 다음과 같다.

```python
[360, 240, 270, 180]
```

이 중 `270`과 `180`이 각각 한 번씩 등장했으므로 `answer`에 2를 더한다.

```python
answer += count.get(270, 0)  # 1
answer += count.get(180, 0)  # 1
```

`count.get(candidate, 0)`은 `candidate`가 딕셔너리에 있으면 해당 인원수를 반환하고, 없으면 0을 반환한다.

## 5️⃣ 주의할 점

현재 풀이는 `2/3`, `3/4`, `1/2`를 사용하기 때문에 실수 연산이 발생한다.

```python
weights[i] * (2/3)
```

파이썬의 실수는 일부 값을 정확하게 표현하지 못하기 때문에, 딕셔너리의 키를 비교할 때 예상하지 못한 문제가 생길 수 있다. 따라서 비율을 정수 연산으로 처리하는 편이 더 안전하다.

```python
def solution(weights):
    answer = 0
    weights.sort()
    count = {}

    for weight in weights:
        # 같은 몸무게
        answer += count.get(weight, 0)

        # weight × 1/2
        if weight % 2 == 0:
            answer += count.get(weight // 2, 0)

        # weight × 2/3
        if weight % 3 == 0:
            answer += count.get(weight * 2 // 3, 0)

        # weight × 3/4
        if weight % 4 == 0:
            answer += count.get(weight * 3 // 4, 0)

        count[weight] = count.get(weight, 0) + 1

    return answer
```

나누어떨어지는 경우에만 후보를 확인하므로 소수 몸무게가 만들어지는 경우도 자연스럽게 제외할 수 있다.

## 6️⃣ 시간복잡도

### 첫 번째 풀이

모든 두 사람의 조합을 직접 비교한다.

$$
O(N^2)
$$

### 개선한 풀이

- 몸무게 정렬: \(O(N\log N)\)
- 각 몸무게마다 후보 4개 확인: \(O(4N)=O(N)\)
- 딕셔너리 조회 및 삽입: 평균 \(O(1)\)

따라서 전체 시간복잡도는 다음과 같다.

$$
O(N\log N)
$$

추가로 사용하는 딕셔너리의 공간복잡도는 최악의 경우 \(O(N)\)이다. 다만 이 문제에서 몸무게는 100 이상 1,000 이하이므로 실제로 저장되는 서로 다른 키의 수는 최대 901개이다.

## 7️⃣ 정리

이번 풀이에서는 입력의 길이가 최대 \(10^5\)인데도 모든 쌍을 직접 비교해 시간 초과가 발생했다.

처음에는 “두 사람을 어떻게 비교할 것인가”에만 집중했지만, 실제로는 “현재 사람과 짝이 될 수 있는 몸무게가 무엇인가”를 먼저 구하는 것이 핵심이었다.

짝이 될 수 있는 몸무게가 네 종류로 제한되므로 이전 몸무게의 등장 횟수를 딕셔너리에 저장하면, 모든 사람을 다시 순회하지 않고 필요한 후보만 확인할 수 있다.

앞으로 입력 크기가 큰 조합 문제에서는 바로 이중 반복문을 사용하기 전에 다음을 먼저 확인해야겠다.

- 비교 대상의 조건이 제한되어 있는가?
- 이전에 나온 값을 저장해 재사용할 수 있는가?
- 딕셔너리를 이용해 탐색을 \(O(1)\)로 줄일 수 있는가?
