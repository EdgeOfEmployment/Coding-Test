# 롤케이크 자르기

## 문제 링크

[프로그래머스 - 롤케이크 자르기](https://school.programmers.co.kr/learn/courses/30/lessons/132265)

---

## 문제 해결 과정

처음에는 롤케이크를 왼쪽과 오른쪽 배열 두 개로 나누어 관리하려고 했다.

```text
왼쪽 배열 ← 토핑을 하나씩 이동 ← 오른쪽 배열
```

오른쪽에 모든 토핑을 넣어놓고 하나씩 왼쪽으로 옮기면서 두 조각의 토핑 종류를 비교하려고 했다.

하지만 배열을 이용하면 **현재 왼쪽과 오른쪽에 어떤 종류의 토핑이 존재하는지 확인하는 과정이 복잡해진다.**

특히 같은 토핑이 여러 개 존재하기 때문에 단순히 토핑 하나를 옮겼다고 해서 오른쪽에서 해당 토핑 종류를 바로 제거할 수 없었다.

그래서 **중복을 자동으로 제거하여 토핑의 종류를 관리할 수 있는 `Set`을 사용**하기로 했다.

---

## 1. Set을 사용하는 이유

이 문제에서는 토핑의 **개수**가 아니라 토핑의 **종류의 개수**가 중요하다.

예를 들어,

```text
[1, 2, 1, 3]
```

에는 토핑이 4개 있지만 토핑의 종류는

```text
1, 2, 3
```

으로 3종류이다.

`HashSet`은 중복된 값을 하나만 저장하기 때문에 토핑 종류를 쉽게 관리할 수 있다.

```java
Set<Integer> left = new HashSet<>();
Set<Integer> right = new HashSet<>();
```

따라서

```java
left.size()
```

는 왼쪽에 존재하는 토핑 종류의 수이고,

```java
right.size()
```

는 오른쪽에 존재하는 토핑 종류의 수이다.

---

## 2. 처음에는 모든 토핑을 오른쪽에 넣는다

처음에는 아직 케이크를 자르지 않았기 때문에 모든 토핑이 오른쪽에 있다고 생각한다.

```java
for (int i = 0; i < n; i++) {
    right.add(topping[i]);
}
```

예를 들어 다음과 같은 토핑이 있다면,

```text
[1, 2, 1, 3, 1, 4, 1, 2]
```

처음 상태는 다음과 같다.

```text
왼쪽                         오른쪽

[]                           [1, 2, 1, 3, 1, 4, 1, 2]
```

Set으로 관리하면:

```text
left  = {}
right = {1, 2, 3, 4}
```

따라서 오른쪽에는 4종류의 토핑이 존재한다.

---

## 3. Set만 사용했을 때 발생하는 문제

처음에는 단순하게 토핑을 왼쪽으로 옮기면서

```java
right.remove(topping[i]);
```

하면 된다고 생각했다.

하지만 이것은 문제가 있다.

예를 들어 오른쪽에

```text
[1, 2, 1, 3]
```

이 있다고 하자.

여기서 `1`을 하나 왼쪽으로 옮겼다고 해서

```java
right.remove(1);
```

을 실행하면 안 된다.

왜냐하면 오른쪽에는 아직 `1`이 하나 더 남아있기 때문이다.

즉 `Set`은

```text
{1, 2, 3}
```

처럼 **종류만 저장하고 개수는 저장하지 않는다.**

따라서 오른쪽에 해당 토핑이 몇 개 남아있는지 별도로 관리해야 했다.

---

## 4. count 배열 사용

토핑 번호별로 오른쪽에 남아 있는 토핑의 개수를 저장하기 위해 `count` 배열을 사용한다.

```java
int[] count = new int[10001];
```

문제에서 토핑 번호의 범위가

```text
1 ~ 10,000
```

이기 때문에 토핑 번호를 배열의 인덱스로 사용할 수 있다.

즉,

```text
count[토핑 번호]
```

에는 해당 토핑이 오른쪽에 몇 개 남아있는지를 저장한다.

처음에는 모든 토핑이 오른쪽에 있기 때문에:

```java
for (int i = 0; i < n; i++) {
    right.add(topping[i]);
    count[topping[i]]++;
}
```

를 실행한다.

예를 들어:

```text
topping = [1, 2, 1, 3, 1]
```

이라면:

```text
count[1] = 3
count[2] = 1
count[3] = 1
```

이 된다.

---

## 5. 토핑을 하나씩 왼쪽으로 이동

이제 왼쪽으로 토핑을 하나씩 옮긴다.

```java
for (int i = 0; i < n - 1; i++) {
```

마지막 토핑까지 옮기면 오른쪽 조각이 없어지기 때문에 `n - 1`까지만 확인한다.

토핑을 왼쪽으로 옮기는 과정은:

```java
left.add(topping[i]);
```

이다.

예를 들어 처음 토핑 `1`을 옮기면:

```text
왼쪽                         오른쪽

[1]                          [1, 2, 1, 3, 1, 4, 1, 2]
```

왼쪽 Set은:

```text
left = {1}
```

이 된다.

---

## 6. 오른쪽 토핑 개수 감소

토핑 하나를 왼쪽으로 옮겼으므로 오른쪽에 남아 있는 해당 토핑의 개수를 감소시킨다.

```java
count[topping[i]]--;
```

예를 들어 오른쪽에 `1`이 4개 있었다면:

```text
count[1] = 4
```

토핑 하나를 왼쪽으로 옮긴 후:

```text
count[1] = 3
```

이 된다.

---

## 7. 오른쪽에서 토핑 종류 제거

토핑의 개수가 `0`이 되었다면 오른쪽에서 해당 토핑 종류가 완전히 사라진 것이다.

```java
if (count[topping[i]] == 0) {
    right.remove(topping[i]);
}
```

예를 들어:

```text
count[1] = 1
```

인 상태에서 마지막 `1`을 왼쪽으로 옮기면:

```text
count[1] = 0
```

이 된다.

이때 오른쪽에는 더 이상 `1`이 존재하지 않으므로:

```java
right.remove(1);
```

을 실행한다.

이렇게 `count` 배열을 이용하면 **중복된 토핑이 오른쪽에 남아있는지 정확하게 확인할 수 있다.**

---

## 8. 공평하게 나누어졌는지 확인

왼쪽과 오른쪽의 토핑 종류 수가 같다면 공평하게 나누어진 것이다.

Set을 사용하고 있기 때문에 `size()`로 종류의 개수를 확인할 수 있다.

```java
if (left.size() == right.size()) {
    answer++;
}
```

예를 들어:

```text
왼쪽  = [1, 2, 1, 3]
오른쪽 = [1, 4, 1, 2]
```

라면:

```text
left  = {1, 2, 3}
right = {1, 2, 4}
```

두 Set의 크기는 모두 3이다.

```text
left.size()  = 3
right.size() = 3
```

따라서 이 위치에서 자르는 것은 공평한 방법이며 `answer`를 증가시킨다.

---


## 9. 풀이 핵심 정리

이 문제에서 사용한 자료구조의 역할은 다음과 같다.

| 자료구조     | 역할                     |
| -------- | ---------------------- |
| `left`   | 왼쪽에 존재하는 토핑 종류 저장      |
| `right`  | 오른쪽에 존재하는 토핑 종류 저장     |
| `count`  | 오른쪽에 각 토핑이 몇 개 남았는지 저장 |
| `answer` | 공평하게 자를 수 있는 위치의 개수    |

전체적인 흐름은 다음과 같다.

```text
① 모든 토핑을 right에 넣는다.
        ↓
② count에 토핑별 개수를 저장한다.
        ↓
③ 토핑을 하나씩 left로 옮긴다.
        ↓
④ count에서 해당 토핑의 개수를 1 감소시킨다.
        ↓
⑤ count가 0이면 right에서 해당 토핑 종류를 제거한다.
        ↓
⑥ left.size() == right.size()인지 확인한다.
        ↓
⑦ 같다면 answer++
```


## 느낀 점

처음에는 배열 두 개를 만들어 오른쪽에서 왼쪽으로 토핑을 하나씩 이동시키는 방식으로 접근했다. 하지만 토핑의 종류를 확인하는 과정에서 같은 토핑이 여러 개 존재하는 경우를 처리하기 어려웠다.

이후 `Set`을 사용하면 중복을 제거하여 토핑의 종류를 쉽게 관리할 수 있다는 것을 알게 되었다. 하지만 `Set`만으로는 같은 토핑이 오른쪽에 몇 개 남아있는지 알 수 없다는 문제가 다시 발생했다.

이를 해결하기 위해 `count` 배열을 추가하여 **Set은 토핑의 종류를 관리하고, count는 오른쪽에 남아있는 토핑의 개수를 관리하도록 역할을 나누었다.**

이를 통해 처음 생각했던 **"오른쪽에 모든 토핑을 넣고 하나씩 왼쪽으로 넘기면서 비교한다"**는 접근 방식을 유지하면서 효율적으로 문제를 해결할 수 있었다.
