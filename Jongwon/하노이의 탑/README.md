# 하노이의 탑

## 문제 링크

[프로그래머스 - 하노이의 탑](https://school.programmers.co.kr/learn/courses/30/lessons/12946)

## 문제 해결 방법

처음에는 원판을 하나씩 옮기면서 이동 경로를 저장하면 된다고 생각했다. 문제에서 요구하는 결과가 출발 기둥과 도착 기둥을 나타내는 배열이었기 때문에, 원판을 옮길 때마다 이동 기록을 저장하는 방식으로 접근했다.

이동 기록을 저장하기 위해 `List<int[]>`를 사용했다. 배열은 크기가 정해져 있지만, 리스트는 `add()`를 사용해 이동 기록을 하나씩 추가할 수 있기 때문이다.

```java
List<int[]> list = new ArrayList<>();
```

이동할 때마다 출발 기둥과 도착 기둥을 하나의 배열로 만들어 리스트에 저장했다.

```java
list.add(new int[]{start, end});
```

예를 들어 1번 기둥에서 3번 기둥으로 이동하면 `{1, 3}`이 저장된다. 이처럼 모든 이동 과정을 기록한 다음, 마지막에 리스트를 2차원 배열로 변환해 반환하도록 했다.

```java
return list.toArray(new int[list.size()][]);
```

## 재귀를 이용한 문제 해결

문제를 풀면서 가장 어려웠던 부분은 하노이의 탑을 재귀로 구현하는 것이었다.

처음에는 `hanoi()` 메서드를 다시 호출한다는 개념이 익숙하지 않았고, `start`, `mid`, `end`의 순서를 바꿔서 전달하는 이유도 이해하기 어려웠다.

AI의 도움을 받아 원판을 옮기는 과정을 세 단계로 나누어 생각할 수 있다는 것을 알게 되었다.

1. 출발 기둥에 있는 작은 원판들을 보조 기둥으로 옮긴다.
2. 가장 큰 원판을 출발 기둥에서 목적지로 옮긴다.
3. 보조 기둥에 있는 작은 원판들을 목적지로 옮긴다.

이 과정을 코드로 작성하면 다음과 같다.

```java
hanoi(n - 1, start, end, mid);

list.add(new int[]{start, end});

hanoi(n - 1, mid, start, end);
```

첫 번째 재귀 호출에서는 큰 원판을 옮기기 위해 작은 원판들을 보조 기둥으로 옮긴다. 두 번째 단계에서는 가장 큰 원판의 이동 기록을 저장하고, 마지막 재귀 호출에서는 작은 원판들을 목적지로 옮긴다.

## 기둥의 순서를 바꾸는 이유

처음에는 `hanoi(n, start, mid, end)`로 메서드를 정의했기 때문에, 호출할 때도 항상 `start`, `mid`, `end` 순서로 작성해야 한다고 생각했다.

하지만 재귀 호출에서는 각 기둥의 역할에 따라 전달하는 값을 바꿀 수 있다는 것을 알게 되었다.

```java
hanoi(n - 1, start, end, mid);
```

이 코드는 작은 원판들을 원래의 보조 기둥으로 옮기기 위한 호출이다. 함수의 매개변수 순서는 그대로지만, 전달하는 값을 바꾸면 새로 호출된 메서드에서는 각 기둥의 역할이 달라진다.

예를 들어 처음에 `hanoi(2, 1, 2, 3)`을 호출하면, 첫 번째 재귀 호출은 `hanoi(1, 1, 3, 2)`가 된다. 따라서 작은 원판을 1번에서 2번으로 옮길 수 있다.

이 부분을 이해하는 데 시간이 많이 걸렸지만, 실제로 전달되는 값을 표로 정리하면서 기둥의 역할이 달라진다는 것을 이해할 수 있었다.

## 원판이 하나일 때 처리하기

재귀 호출을 언제 끝내야 하는지도 중요했다.

```java
if (n == 1) {
    list.add(new int[]{start, end});
}
```

원판이 하나라면 다른 원판을 치울 필요 없이 출발 기둥에서 목적지로 바로 옮기면 된다. 따라서 이동 기록을 저장하고 더 이상 재귀 호출을 하지 않도록 했다.

이처럼 재귀 호출을 멈추는 조건을 기저 조건이라고 한다.

## 최종 코드

```java
import java.util.*;

class Solution {
    List<int[]> list = new ArrayList<>();

    public int[][] solution(int n) {
        hanoi(n, 1, 2, 3);

        return list.toArray(new int[list.size()][]);
    }

    public void hanoi(int n, int start, int mid, int end) {
        if (n == 1) {
            list.add(new int[]{start, end});
        } else {
            hanoi(n - 1, start, end, mid);

            list.add(new int[]{start, end});

            hanoi(n - 1, mid, start, end);
        }
    }
}
```

## 어려웠던 점

이번 문제는 지금까지 풀었던 문제 중에서도 재귀의 동작 과정을 이해하는 데 특히 어려움이 있었다.

처음에는 원판을 옮기는 순서는 이해했지만, 이를 재귀 호출로 어떻게 표현해야 하는지 알기 어려웠다. 특히 `hanoi(n - 1, start, end, mid)`처럼 `mid`와 `end`의 순서를 바꿔 전달하는 이유를 이해하는 데 시간이 걸렸다.

혼자서 바로 해결하기는 어려워 AI의 도움을 많이 받았지만, 설명을 듣고 `n = 2`일 때의 이동 과정을 하나씩 따라가면서 재귀 호출이 어떤 순서로 실행되는지 이해하려고 노력했다.

이번 문제를 통해 재귀는 단순히 같은 메서드를 다시 호출하는 것이 아니라, **큰 문제를 더 작은 문제로 나누고 같은 해결 과정을 반복하는 방법**이라는 것을 배웠다. 아직 재귀를 자유롭게 활용하기는 어렵지만, 호출할 때 전달하는 값과 각 단계의 역할을 직접 확인하는 연습이 필요하다는 것을 느꼈다.
