# 과제 진행하기 - 코드 풀이

## 문제 해결 방법

처음에는 현재 과제의 종료 시간과 다음 과제의 시작 시간만 비교하면 해결할 수 있다고 생각하였다.

따라서 시작 시간을 기준으로 정렬한 뒤,

- 현재 과제가 다음 과제 시작 전에 끝나는 경우 → 완료 처리
- 끝나지 못하는 경우 → 잠시 멈춤

하는 방식으로 접근하였다.

하지만 단순히 현재 과제만 관리하는 방식으로는 문제가 있었다.

이전 과제가 멈춘 상태에서 새로운 과제가 시작되고, 이후 다시 멈춘 과제를 이어서 수행해야 하는 상황이 발생하기 때문이다.

또한 문제 조건에서

> 가장 최근에 멈춘 과제부터 다시 시작한다.

라는 조건이 있기 때문에, 멈춘 과제들을 저장할 공간이 필요했다.

따라서 **Stack 구조를 활용하여 멈춘 과제와 남은 시간을 저장**하고, 현재 과제를 끝낸 후 남는 시간 동안 Stack에 있는 과제를 다시 수행하는 방식으로 해결하였다.

---

## 1. 과제를 시작 시간 기준으로 정렬

```java
Arrays.sort(plans, (a,b) -> a[1].compareTo(b[1]));
```

입력된 과제는 시작 시간 순서대로 들어오지 않을 수 있기 때문에 먼저 시작 시간을 기준으로 정렬한다.

정렬 후에는 항상 현재 과제와 다음 과제를 순서대로 비교할 수 있다.

---

## 2. 시간을 분 단위로 변환

```java
int nowSum = nowHour * 60 + nowMin;
int nextSum = nextHour * 60 + nextMin;
```

시간 비교를 쉽게 하기 위해 `"HH:MM"` 형식의 시간을 모두 분으로 변환한다.

예를 들어

```
12:30
```

은

```
12 * 60 + 30 = 750분
```

으로 변환된다.

---

## 3. 현재 과제 종료 시간 계산

```java
int finishTime = nowSum + playtime;
```

현재 과제의 시작 시간과 수행 시간을 더해 종료 시간을 구한다.

이후 종료 시간과 다음 과제 시작 시간을 비교하여 현재 과제를 완료할 수 있는지 판단한다.

---

## 4. 현재 과제를 끝낼 수 있는 경우

```java
if(finishTime <= nextSum)
```

현재 과제가 다음 과제가 시작되기 전에 끝나는 경우이다.

현재 과제를 완료 목록에 추가한다.

```java
task.add(plans[i][0]);
```

이후 다음 과제가 시작하기 전까지 남는 시간이 있다면, Stack에 저장되어 있던 멈춘 과제를 다시 수행한다.

```java
while(remainTime > 0 && !stop.isEmpty())
```

Stack은 가장 최근에 저장된 과제가 먼저 나오기 때문에 문제 조건인

```
가장 최근에 멈춘 과제부터 수행
```

을 만족한다.

---

## 5. 멈춘 과제를 다시 수행하는 경우

Stack에는 다음 정보를 저장한다.

```
[과제 이름, 남은 시간]
```

예시

```
[music, 30]
```

은 music 과제가 30분 남았다는 의미이다.


Stack에서 과제를 꺼낸 후 남는 시간 안에 끝낼 수 있는지 확인한다.

```java
if(time <= remainTime)
```

끝낼 수 있다면 완료 목록에 추가한다.

```java
task.add(name);
remainTime -= time;
```

남는 시간이 있다면 다음 멈춘 과제를 이어서 수행한다.


---

## 6. 멈춘 과제를 끝내지 못하는 경우

```java
stop.push(new String[]{
    name,
    String.valueOf(time - remainTime)
});
```

남는 시간이 부족해서 과제를 완료하지 못한다면,

수행하고 남은 시간을 다시 Stack에 저장한다.

예를 들어

```
남은 시간 : 10분

과제 남은 시간 : 30분
```

이라면

```
20분 남음
```

상태로 다시 저장한다.

---

## 7. 현재 과제를 끝내지 못하는 경우

```java
else{
    stop.push(new String[]{
        plans[i][0],
        String.valueOf(leftTime)
    });
}
```

현재 과제가 다음 과제 시작 전까지 끝나지 않는 경우이다.

따라서 현재 과제를 중단하고

- 과제 이름
- 남은 수행 시간

을 Stack에 저장한다.

이후 새로운 과제가 시작된다.

---

## 8. 마지막 과제 처리

반복문에서는 현재 과제와 다음 과제를 비교하기 때문에 마지막 과제는 처리되지 않는다.

따라서 반복문 이후 마지막 과제를 완료 처리한다.

```java
task.add(plans[n-1][0]);
```

---

## 9. 남아있는 멈춘 과제 처리

마지막 과제가 끝난 후에는 더 이상 새로운 과제가 없다.

따라서 Stack에 남아있는 과제들을 모두 꺼내 완료 처리한다.

```java
while(!stop.isEmpty()){
    task.add(stop.pop()[0]);
}
```

Stack 구조이기 때문에 가장 최근에 멈춘 과제부터 완료된다.

---

## 사용한 자료구조

### Deque<String[]>

멈춘 과제를 저장하기 위해 Stack으로 사용하였다.

저장하는 값:

- 과제 이름
- 남은 수행 시간


Stack을 사용한 이유:

- 마지막에 넣은 과제가 먼저 나와야 한다.
- 문제 조건인 "가장 최근에 멈춘 과제부터 수행"을 만족한다.

---

### List<String>

완료한 과제의 순서를 저장하기 위해 사용하였다.

마지막에 배열로 변환하여 반환한다.

---

## 시간 복잡도

과제의 개수를 N이라고 하면

- 시작 시간 정렬 : `O(N log N)`
- 각 과제는 Stack에 최대 한 번 저장되고 한 번 제거된다.

따라서 전체 시간 복잡도는

```
O(N log N)
```

이다.

---

## 공간 복잡도

최악의 경우 모든 과제가 Stack에 저장될 수 있으므로

```
O(N)
```

의 공간 복잡도를 가진다.

---

## 배운 점

처음에는 단순히 현재 과제와 다음 과제의 시간만 비교하면 된다고 생각했지만,

이 문제는 이전에 중단된 과제들의 상태까지 관리해야 하는 **시뮬레이션 문제**였다.

특히

- 현재 과제가 남은 시간
- 다음 과제 시작 전까지 사용할 수 있는 시간

을 구분하는 것이 중요했고,

문제 조건의 "가장 최근에 멈춘 과제부터 수행"이라는 부분을 통해 Stack 자료구조를 활용하는 방법을 배울 수 있었다.
