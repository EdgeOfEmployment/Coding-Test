# 공 이동 시뮬레이션 문제 풀이 공유

[문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/87391)

## 1. 접근법과 단순 풀이의 한계

격자의 한 칸에 공을 놓고 쿼리를 순서대로 실행하면 공이 상하좌우로 움직입니다. **격자 밖으로는 나갈 수 없어서 벽에 부딪히면 거기서 멈춥니다.** 모든 칸에 공을 하나씩 놓고 돌렸을 때 **도착점이 `(x, y)`가 되는 시작점이 몇 개인지** 세는 문제입니다.

문제가 시키는 대로 짜면 "모든 칸에서 출발해 쿼리를 전부 실행해 보고, 도착점이 맞으면 카운트"가 됩니다.

<details>
<summary>처음 작성한 시간초과 코드 (펼치기)</summary>

```python
## 시간초과 (입력값이 10의 9승)
def solution(n, m, x, y, queries):
    answer = 0
    last_n = n-1
    last_m = m-1

    # 시작점마다 모든 쿼리 실행
    for a in range(n):
        for b in range(m):
            start, end = a, b # 시작점 초기화

            for command, dx in queries:
                if command == 0:
                    if end - dx < 0:
                        end = 0
                    else:
                        end -= dx
                elif command == 1:
                    if end + dx > last_m:
                        end = last_m
                    else:
                        end += dx
                elif command == 2:
                    if start - dx < 0:
                        start = 0
                    else:
                        start -= dx
                else:
                    if start + dx > last_n:
                        start = last_n
                    else:
                        start += dx

            if start == x and end == y:
                answer += 1

    return answer
```

</details>

동작 자체는 맞지만 **격자가 최대 $10^9 \times 10^9$**, 쿼리는 최대 20만 개입니다. 칸 수만 $10^{18}$개라서 시작점을 하나씩 놓아 보는 순간 끝입니다. **1초에 1억 칸씩 처리해도 수백 년이 걸리는 규모**라, 반복문을 아무리 최적화해도 이 방향으로는 답이 없습니다.

- **방향 수정**: "모든 시작점을 굴려서 도착점을 확인"하는 대신, **도착점 `(x, y)` 하나에서 출발해 쿼리를 거꾸로 되감으며 "시작점이 될 수 있는 범위"를 추적**하는 방식으로 바꿨습니다. 이러면 격자 크기와 무관하게 **쿼리 개수만큼만** 계산하면 끝납니다.

## 2. 해결 코드

```python
def solution(n, m, x, y, queries):
    ## 커맨드
    ## 열 번호 감소 : 0, dx
    ## 열 번호 증가 : 1, dx
    ## 행 번호 감소 : 2, dx
    ## 행 번호 증가 : 3, dx

    ## 격자가 최대 10^9 x 10^9라 시작점을 하나씩 돌리면 시간초과
    ## -> 도착점 (x, y)에서 쿼리를 거꾸로 되감으며 "시작점이 될 수 있는 범위"를 추적

    last_n = n-1
    last_m = m-1

    # 도착점(x, y)에서 시작해 역추적할 시작점의 행/열 범위 초기화
    row_min, row_max = x, x
    col_min, col_max = y, y

    # 시뮬레이션 역순 진행
    for command, dx in reversed(queries):
        if command == 0:  # 원래: 왼쪽(열 감소) -> 역순: 오른쪽으로 이동/확장
            if col_min != 0:
                col_min += dx
            col_max += dx
            if col_max > last_m:
                col_max = last_m

        elif command == 1:  # 원래: 오른쪽(열 증가) -> 역순: 왼쪽으로 이동/확장
            if col_max != last_m:
                col_max -= dx
            col_min -= dx
            if col_min < 0:
                col_min = 0

        elif command == 2:  # 원래: 위쪽(행 감소) -> 역순: 아래쪽으로 이동/확장
            if row_min != 0:
                row_min += dx
            row_max += dx
            if row_max > last_n:
                row_max = last_n

        elif command == 3:  # 원래: 아래쪽(행 증가) -> 역순: 위쪽으로 이동/확장
            if row_max != last_n:
                row_max -= dx
            row_min -= dx
            if row_min < 0:
                row_min = 0

        # 만약 유효한 범위를 완전히 벗어난다면 가능한 시작점은 없음
        if row_min > last_n or row_max < 0 or col_min > last_m or col_max < 0:
            return 0

    # 최종적으로 가능한 행 개수와 열 개수를 곱한 값 반환
    return (row_max - row_min + 1) * (col_max - col_min + 1)
```

## 3. 구현 전략 및 이유

### 거꾸로 되감는다는 게 무슨 뜻인가

정방향 풀이는 **"이 칸에서 출발하면 어디에 도착하지?"** 를 묻습니다. 역방향 풀이는 반대로 **"여기에 도착하려면 직전에 어디 있었어야 하지?"** 를 묻습니다.

열이 0~5인 격자에서 마지막 쿼리가 **"왼쪽으로 2칸"** 이고 도착한 열이 3이라면, 그 직전에 공은 열 **5**에 있었어야 합니다. `3 + 2 = 5`, 즉 **이동 방향의 반대로 되돌리는** 것입니다. 이 되감기를 마지막 쿼리부터 첫 쿼리까지 거슬러 올라가면, 마지막에 남는 것이 곧 **가능한 시작점**입니다.

`reversed(queries)`로 뒤에서부터 도는 이유, 그리고 원래 왼쪽 이동인 `command == 0`에서 코드가 오히려 `+= dx`를 하는 이유가 이것입니다.

### 왜 점 하나가 아니라 '범위'를 들고 다니는가

되감는다고 답이 항상 한 점으로 나오지는 않습니다. **벽 때문**입니다. 같은 격자에서 "왼쪽으로 2칸" 명령을 받고 **열 0에 도착한** 공은, 직전에 **0, 1, 2 중 어디에 있었든** 똑같이 벽에 눌려 0이 됩니다. 후보가 하나에서 여러 개로 **늘어나는** 것입니다.

그래서 점 대신 **`[row_min, row_max]`와 `[col_min, col_max]`라는 구간 두 개**를 들고 다닙니다. `(x, y)` 한 점에서 시작해(`row_min = row_max = x`) 되감을 때마다 이 구간을 옮기거나 늘립니다.

후보를 이렇게 **빈틈없는 직사각형**으로 봐도 되는 근거는 두 가지입니다.

- **공끼리 서로 추월하지 못합니다.** 모든 공이 똑같은 명령을 받으므로 왼쪽에 있던 공이 오른쪽 공을 앞지를 수 없고, 벽에서 뭉치기만 합니다. 따라서 같은 곳에 도착하는 시작점들은 항상 **붙어 있는 한 덩어리**입니다. 중간에 구멍이 뚫릴 수 없으니 양 끝만 알면 충분합니다.
- **행과 열이 서로 간섭하지 않습니다.** 위아래 명령은 행만, 좌우 명령은 열만 바꿉니다. 그래서 행 후보와 열 후보를 따로 구한 뒤 **마지막에 곱하면**(`(row_max - row_min + 1) * (col_max - col_min + 1)`) 전체 시작점 개수가 나옵니다.

### 벽에 붙은 쪽은 되돌리지 않는 이유 (제일 헷갈리는 부분)

코드에서 가장 이해하기 어려운 부분이 `if col_min != 0:` 같은 조건입니다. 위의 예를 표로 정리하면 이렇습니다. (열이 0~5인 격자, 명령은 "왼쪽으로 2칸")

| 지금 후보 | 직전에 있을 수 있던 자리 | 이유 |
|---|---|---|
| 열 3 | 열 5 | 3에 오려면 5에서 왼쪽으로 2칸 |
| 열 **0** | 열 **0 ~ 2** | 0, 1, 2 전부 벽에 막혀 0으로 눌림 |

즉 **후보 구간의 아래 끝이 벽(0)에 딱 붙어 있으면, 되감은 뒤에도 아래 끝은 0으로 둬야** 벽에 눌려서 온 공들을 놓치지 않습니다. 벽에 붙어 있지 않다면 정직하게 `+ dx` 해 주면 됩니다. 네 개의 분기가 전부 이 모양입니다.

- **왼쪽 이동(0) 되감기** → 아래 끝이 0이면 그대로 두고, 위 끝은 `+ dx`
- **오른쪽 이동(1) 되감기** → 위 끝이 `last_m`이면 그대로 두고, 아래 끝은 `- dx`
- **행 이동(2, 3)** → `last_n`을 기준으로 똑같은 규칙

되돌린 뒤 `last_m`이나 0으로 다시 잘라 주는 것도 같은 맥락입니다. 시작점은 **격자 안**에 있어야 하므로, 격자를 벗어난 부분은 애초에 후보가 될 수 없습니다.

### 중간에 `return 0`을 하는 이유

되감다 보면 후보 구간이 격자 **밖으로 통째로 밀려나는** 경우가 생깁니다. 예를 들어 후보 열의 아래 끝이 `last_m`보다 커지면, 그런 자리에는 공을 놓을 수 없으니 **`(x, y)`에 도착하는 방법이 아예 없다**는 뜻입니다. 더 볼 것 없이 0을 돌려줍니다.

### 시간 및 공간 복잡도

- **시간 복잡도**: $O(Q)$ ($Q$는 쿼리 개수(최대 200,000)입니다. 쿼리 하나당 상수 번의 덧셈과 비교만 하고, **격자 크기 $n$, $m$은 계산량에 전혀 영향을 주지 않습니다.**)
- **공간 복잡도**: $O(1)$ (행/열의 경계 값 네 개 외에는 아무것도 저장하지 않습니다.)
