# 택배 배달과 수거하기 문제 풀이 공유

[문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/150369)

## 1. 접근법과 단순 풀이의 한계

물류창고(0번 지점)에서 출발한 트럭이 최대 `cap`개까지 실을 수 있고, 배달과 수거를 모두 마친 뒤 창고로 돌아와야 합니다. 이동한 **최소 거리**를 구하는 문제입니다.

- **배달과 수거를 따로 왕복하는 접근의 한계**: 가장 먼저 떠오르는 건 배달을 전부 끝내고 수거를 도는 방식입니다. 하지만 트럭은 **배달 상자를 내려놓은 자리에서 곧바로 수거 상자를 실을 수 있으므로**, 한 번의 왕복에서 두 작업을 동시에 처리해도 거리가 전혀 늘지 않습니다. 입출력 예 #1에서 따로 돌면 배달 16 + 수거 12 = **28**이 되어 정답 16의 두 배 가까이 나옵니다.
- **가까운 집부터 채우는 그리디의 한계**: 창고에서 가까운 집부터 트럭을 채우면, 가까운 집들을 처리하느라 짧은 왕복을 여러 번 하고 **먼 집은 결국 나중에 또 가야 합니다.** 반대로 먼 집을 갈 때는 가는 길에 있는 가까운 집을 **덤으로 처리할 수 있으므로**, 먼 집을 우선하는 편이 항상 이득입니다. 입출력 예 #1에서 가까운 집부터 채우면 18, #2에서는 32가 나와 정답(16, 30)을 넘습니다.
- **왕복마다 집을 훑는 시뮬레이션의 한계**: 방향을 먼 집부터로 바로잡아도, 왕복할 때마다 배열을 순회하며 트럭을 채우는 식으로 구현하면 집이 최대 100,000개인데 `cap`이 1이고 물량이 많은 경우 왕복 횟수가 폭발해 시간 초과가 납니다.
- **방향 수정**: **한 번의 왕복 비용은 그 왕복에서 가장 멀리 간 집까지의 거리 × 2로 고정**이라는 점에 주목해, 배열을 **뒤에서 앞으로 한 번만 훑으면서** 각 집에서 필요한 왕복 횟수만 세는 방식으로 전환했습니다.

## 2. 해결 코드

```python
def solution(cap, n, deliveries, pickups):
    ## 트럭은 항상 물류창고(0번 지점)에서 출발해 돌아와야 하므로
    ## 한 번의 왕복 비용은 "그 왕복에서 가장 멀리 간 집까지의 거리 x 2"로 고정된다.
    ## 배달과 수거는 같은 왕복 안에서 함께 처리해도 추가 비용이 없다.
    ## -> 가장 먼 집부터 역순으로 훑으면서, 그 집을 처리하는 데 필요한 왕복 횟수만 세면 된다.

    ## 남은 물량을 음수로 관리한다.
    ## 음수면 아직 처리하지 못한 상자가 남은 것이고, 양수면 이번 왕복에서 쓰고 남은 여유 적재량이다.

    answer = 0
    d_rest = 0  # 배달 여유 적재량 (음수면 배달하지 못하고 남은 상자 수)
    p_rest = 0  # 수거 여유 적재량 (음수면 수거하지 못하고 남은 상자 수)

    # 1. 물류창고에서 먼 집부터 역순으로 순회
    for house in range(n - 1, -1, -1):

        # 1-1. 이 집의 물량을 여유 적재량에서 차감
        d_rest -= deliveries[house]
        p_rest -= pickups[house]

        # 1-2. 배달이든 수거든 남은 물량이 있으면 이 집까지 왕복해야 함
        trip = 0
        while d_rest < 0 or p_rest < 0:
            trip += 1
            # 왕복 한 번마다 배달과 수거 모두 cap만큼 여유가 생김
            d_rest += cap
            p_rest += cap

        # 1-3. 이 집이 그 왕복들에서 가장 먼 집이므로 (house + 1) * 2 가 왕복 거리
        answer += trip * (house + 1) * 2

    return answer
```

## 3. 구현 전략 및 이유

### 먼 집부터 역순으로 훑는 이유

트럭은 반드시 창고로 돌아와야 하므로, **한 번의 왕복에서 가장 멀리 간 집이 그 왕복의 비용을 혼자 결정합니다.** `k`번 집까지 갔다면 그보다 가까운 집은 **가는 길과 오는 길에 공짜로 들를 수 있습니다.**

그래서 "가장 먼 집을 언제 처리할 것인가"가 곧 답을 결정합니다. 먼 집을 나중으로 미뤄도 언젠가는 그 거리를 지불해야 하므로, **가장 먼 집으로 가는 왕복에 가까운 집의 물량을 최대한 끼워 넣는** 것이 최선입니다. 배열을 뒤에서부터 훑는 것이 바로 이 전략을 그대로 옮긴 것입니다.

여기서 배달과 수거를 나눌 필요도 사라집니다. 두 작업의 비용이 모두 **"가장 먼 집까지의 거리"** 하나로 계산되므로, 한 왕복에서 배달 `cap`개와 수거 `cap`개를 **동시에** 처리할 수 있습니다. `d_rest`와 `p_rest`를 각각 두되 왕복 한 번에 **둘 다** `cap`씩 늘려 주는 이유가 이것입니다.

### 남은 물량을 음수로 관리하는 이유

변수 하나에 **두 가지 상태를 겹쳐 담기 위해서**입니다.

- **음수**: 아직 처리하지 못하고 밀려 있는 상자 수 → 이 집까지 왕복이 더 필요합니다.
- **0 이상**: 앞선 왕복에서 쓰고 남은 여유 적재량 → 이 집은 **추가 비용 없이** 처리됩니다.

"트럭에 실은 양"과 "남은 물량"을 따로 관리하면 매 집마다 어느 쪽을 갱신할지 분기를 나눠야 하지만, 부호 하나로 합치면 `-= deliveries[house]` 한 줄로 두 경우가 모두 처리됩니다. 값이 0 이상인 동안에는 `while`이 아예 돌지 않아 왕복 횟수도 자연히 0이 됩니다.

`while` 문이 배열 전체에 걸쳐 도는 총 횟수는 **실제 왕복 횟수의 합**과 같고, 이는 $\lceil \sum deliveries / cap \rceil$과 $\lceil \sum pickups / cap \rceil$ 중 큰 값을 넘지 않습니다. 집마다 반복이 중첩되는 구조가 아니므로 전체는 여전히 선형입니다.

### 거리를 `(house + 1) * 2`로 계산하는 이유

`deliveries`와 `pickups`의 인덱스는 0부터 시작하지만 집은 1번부터 셉니다. 즉 `deliveries[house]`는 **`house + 1`번 집**의 물량이고, 창고에서 그 집까지의 거리도 `house + 1`입니다. 갔다가 돌아와야 하므로 왕복 거리는 `(house + 1) * 2`이고, 여기에 왕복 횟수 `trip`을 곱합니다.

### 시간 및 공간 복잡도

- **시간 복잡도**: $O(n + T)$ ($T$는 전체 왕복 횟수로 $\lceil \sum deliveries / cap \rceil$과 $\lceil \sum pickups / cap \rceil$ 중 큰 값입니다. 배열을 한 번만 역순으로 훑고 `while`은 왕복이 실제로 필요할 때만 도므로 사실상 $O(n)$입니다.)
- **공간 복잡도**: $O(1)$ (누적 거리와 여유 적재량 두 개 외에 추가 자료구조를 쓰지 않고, 입력 배열도 변형하지 않습니다.)
