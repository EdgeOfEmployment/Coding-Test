# 디스크 컨트롤러 문제 풀이 공유

[문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/42627)

## 1. 접근법과 단순 풀이의 한계

작업 하나가 걸린 시간은 `끝난 시각 - 요청한 시각`이고, 이 값들의 평균을 가장 작게 만드는 처리 순서를 찾는 문제입니다. 디스크는 한 번에 한 작업만 처리하고, 처리 중에는 멈출 수 없습니다.

먼저 떠오르는 두 가지 순서는 모두 답이 아닙니다.

- **요청이 들어온 순서대로 처리**: 앞의 작업이 오래 걸리면 뒤의 짧은 작업들이 전부 밀립니다. 예제 `[[0, 3], [1, 9], [2, 6]]`을 `0 → 1 → 2` 순으로 처리하면 `(3 + 11 + 16) / 3 = 10`인데, `0 → 2 → 1` 순으로 처리하면 `(3 + 7 + 17) / 3 = 9`로 더 작습니다.
- **소요 시간 순으로 전부 정렬**: 아직 요청도 안 들어온 작업을 먼저 처리하는 순서가 나와 버립니다.

결국 처음에 순서를 한 번에 정할 수는 없고, 시간이 흐르면서 **고를 수 있는 작업이 계속 바뀐다**는 걸 반영해야 합니다.

## 2. 단순 접근 코드

```python
def solution(jobs):
    ## 요청이 들어온 순서대로 처리하는 방식
    ## 예제 [[0, 3], [1, 9], [2, 6]] 에서 10을 반환 (정답은 9)

    jobs.sort(key=lambda job: job[0])

    now = 0
    total = 0
    for start, duration in jobs:
        if now < start:
            now = start
        now += duration
        total += now - start

    return total // len(jobs)
```

## 3. 개선한 접근법

**지금까지 요청된 작업 중 가장 짧은 것부터 처리**하는 방식으로 바꿨습니다.

- 디스크가 비었을 때 고를 수 있는 작업은 **이미 요청이 들어온 작업**뿐입니다. 그중에서 가장 짧은 작업을 먼저 끝내면, 뒤에서 기다리는 작업들의 대기 시간이 그만큼 줄어듭니다.
- 짧은 작업을 빨리 꺼내야 하므로 **최소 힙**을 씁니다. `(소요 시간, 요청 시각)` 순서로 넣으면 소요 시간이 짧은 것부터 나옵니다.
- `jobs`를 요청 시각 순으로 정렬해 두고, 현재 시각까지 요청된 작업만 힙에 넣습니다.
- 힙이 비어 있으면 아직 요청된 작업이 하나도 없다는 뜻이므로, 다음 작업의 요청 시각까지 시간을 건너뜁니다. 이 처리를 빼먹으면 요청 시각 사이에 빈 구간이 있는 입력에서 진행이 멈춥니다.

## 4. 해결 코드

```python
import heapq


def solution(jobs):
    ## 작업 하나가 걸린 시간 = 끝난 시각 - 요청한 시각. 이 값들의 평균을 가장 작게 만들어야 한다.
    ## 요청이 들어온 순서대로 처리하면, 오래 걸리는 작업 뒤에 짧은 작업들이 전부 밀려서 손해다.
    ## 그래서 지금까지 요청된 작업들 중에서 가장 짧은 것부터 처리한다.
    ## 짧은 작업을 빨리 꺼내야 하니까 최소 힙을 쓴다.

    n = len(jobs)

    # 요청이 들어온 순서대로 확인해야 하므로 요청 시각 기준으로 정렬
    jobs.sort(key=lambda job: job[0])

    # 대기 중인 작업들을 담아둘 최소 힙
    # (소요 시간, 요청 시각) 순서로 넣으면 소요 시간이 짧은 것부터 나온다.
    waiting = []

    # 아직 힙에 넣지 않은 작업의 위치
    idx = 0

    # 현재 시각
    now = 0

    # 모든 작업이 걸린 시간의 합
    total = 0

    # 처리한 작업 수
    done = 0

    while done < n:

        # 지금 시각까지 요청이 들어온 작업은 전부 대기열에 넣는다.
        while idx < n and jobs[idx][0] <= now:
            start, duration = jobs[idx]
            heapq.heappush(waiting, (duration, start))
            idx += 1

        # 대기열이 비었다면 아직 요청된 작업이 없다는 뜻이다.
        # 다음 작업이 요청되는 시각까지 시간을 건너뛴다.
        if not waiting:
            now = jobs[idx][0]
            continue

        # 대기 중인 작업 중 가장 짧은 것을 꺼내서 처리한다.
        duration, start = heapq.heappop(waiting)

        # 처리를 끝낸 시각
        now += duration

        # 이 작업이 걸린 시간 = 끝난 시각 - 요청한 시각
        total += now - start

        done += 1

    # 평균 (소수점 아래는 버림)
    return total // n
```

## 5. 구현 전략 및 이유

### 정렬 + 위치 표시로 힙에 넣기
반복할 때마다 `jobs` 전체를 훑으면서 요청됐는지 확인하면 $O(N^2)$이 됩니다. 요청 시각 순으로 미리 정렬해 두고 `idx`를 앞으로만 옮기면 각 작업이 힙에 딱 한 번씩만 들어가서 $O(N \log N)$이 됩니다.

### `(소요 시간, 요청 시각)` 순서로 넣은 이유
파이썬은 튜플을 앞에 있는 값부터 비교하기 때문에, 소요 시간을 앞에 두면 따로 비교 함수를 만들지 않아도 짧은 작업이 먼저 나옵니다. 소요 시간이 같으면 먼저 요청된 작업이 나와서 자연스럽게 처리됩니다.

### 시간 건너뛰기
힙이 비었다는 건 지금 처리할 수 있는 작업이 없다는 뜻이라, `now`를 다음 작업의 요청 시각(`jobs[idx][0]`)으로 옮깁니다. 이 부분이 없으면 요청 시각 사이에 빈 시간이 있는 입력에서 진행이 안 됩니다.

### 검증
작은 입력을 무작위로 만들어서, 가능한 처리 순서를 전부 시도해 본 결과와 비교했고 전부 같은 답이 나왔습니다.

### 시간복잡도
- 시간복잡도: $O(N \log N)$
- 공간복잡도: $O(N)$
