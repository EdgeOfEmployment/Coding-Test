# 다단계 칫솔 판매 문제 풀이 공유

[문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/77486)

## 1. 접근법과 단순 풀이의 한계

판매원과 추천인 관계가 트리 형태로 주어지고, 한 판매원이 칫솔을 팔면 이익의 10%가 추천인에게, 그 추천인이 받은 금액의 10%가 다시 그 위 추천인에게 넘어가며 민호까지 올라가는 구조입니다.

- **조직도를 통째로 순회하려는 접근의 한계**: 추천인 관계를 자식 리스트로 만들어 두고 판매가 일어날 때마다 조직도 전체를 훑으면, `seller`가 최대 100,000건이고 `enroll`이 최대 10,000명이라 매 건마다 전체를 도는 순간 연산량이 감당되지 않습니다. 실제로 필요한 것은 **판매원에서 위쪽으로 이어지는 한 줄뿐**입니다.
- **비율을 미리 곱해서 계산하는 방식의 함정**: "본인이 90%를 가진다"고 보고 `money * 0.9`나 `money * 9 // 10`처럼 한 번에 계산하면, 문제에서 요구하는 **10%를 먼저 버림한 뒤 나머지를 갖는** 규칙과 값이 어긋납니다. 예를 들어 `money = 19`일 때 정답은 `19 - (19 // 10) = 18`이지만, `19 * 9 // 10`은 `17`이 되어 틀립니다.
- **방향 수정**: 이름에서 추천인을 바로 찾을 수 있는 **딕셔너리를 미리 만들어 두고, 판매 건마다 판매원에서 시작해 추천인을 타고 위로 거슬러 올라가며 정수 나눗셈으로 10%씩 떼는** 방식으로 접근을 정리했습니다.

## 2. 해결 코드

```python
def solution(enroll, referral, seller, amount):
    ## 판매원이 칫솔을 팔면 이익의 10%를 자신의 추천인에게 넘기고 나머지를 가진다.
    ## 넘겨받은 추천인도 똑같이 10%를 자신의 추천인에게 넘긴다.
    ## 즉 판매원부터 시작해서 추천인을 타고 위로 올라가며 금액이 1/10씩 줄어드는 구조다.
    ## 민호("-")까지 올라가거나, 넘길 금액이 1원 미만이 되면 분배가 끝난다.

    # 각 판매원의 추천인을 바로 찾을 수 있도록 이름 -> 추천인 매핑을 만든다.
    # 추천인이 "-"인 사람은 민호가 추천인이므로 더 올라갈 곳이 없다는 뜻으로 None을 넣는다.
    parent = {}
    for i, name in enumerate(enroll):
        parent[name] = None if referral[i] == "-" else referral[i]

    # 각 판매원이 최종적으로 가지게 되는 금액
    total = {name: 0 for name in enroll}

    # 판매 기록을 하나씩 처리한다.
    for name, count in zip(seller, amount):

        # 칫솔 한 개의 가격은 100원이다.
        money = count * 100

        # 판매원 본인부터 시작해서 추천인을 타고 위로 올라간다.
        curr = name

        # 민호에게 도달했거나(curr is None), 넘겨받은 금액이 0이 되면 분배를 멈춘다.
        while curr is not None and money > 0:

            # 추천인에게 넘길 10% (1원 미만은 버림 -> 정수 나눗셈)
            fee = money // 10

            # 넘기고 남은 금액은 자신이 가진다.
            # money가 10원 미만이면 fee가 0이 되어 전액을 본인이 가지고 반복이 끝난다.
            total[curr] += money - fee

            # 넘길 금액을 들고 추천인에게 올라간다.
            money = fee
            curr = parent[curr]

    # enroll에 등장하는 순서대로 금액을 반환한다.
    return [total[name] for name in enroll]
```

## 3. 구현 전략 및 이유

### 이름 → 추천인 딕셔너리로 위쪽 한 줄만 따라가기

분배가 필요한 것은 판매원에서 민호까지 이어지는 **한 줄**뿐이므로, 자식 관계는 아예 만들지 않고 `parent[이름] = 추천인` 형태의 딕셔너리 하나만 준비했습니다. 이렇게 하면 `enroll` 리스트에서 이름을 찾는 $O(N)$ 탐색 없이, 매번 $O(1)$로 바로 위 추천인을 얻을 수 있습니다.

추천인이 `"-"`인 사람은 민호가 추천인이라는 뜻이고 민호는 결과에 포함되지 않으므로, 더 올라갈 곳이 없다는 표시로 `None`을 넣어 반복문의 종료 조건으로 그대로 활용했습니다.

### 위에서 아래가 아니라, 아래에서 위로 올라가는 이유

이익은 **판매한 사람에게 전액 발생한 뒤 위로 10%씩 새어 나가는** 구조입니다. 조직도 위쪽에서 아래로 내려가는 방식으로는 어떤 하위 판매원이 얼마를 팔았는지 알아야 계산이 가능해 순서가 꼬입니다. 반대로 판매원에서 시작하면 금액이 정해진 상태에서 위로 한 칸씩만 올라가면 되므로 계산이 한 방향으로 깔끔하게 흐릅니다.

입출력 예 #1의 `young`이 12개(`12 * 100 = 1200원`)를 판 경우를 따라가 보면 다음과 같습니다.

1. **`young`** → 넘길 돈 `1200 // 10 = 120`, 본인이 `1200 - 120 = 1080` 획득
2. **`edward`** (young의 추천인) → 넘길 돈 `120 // 10 = 12`, 본인이 `120 - 12 = 108` 획득
3. **`mary`** (edward의 추천인) → 넘길 돈 `12 // 10 = 1`, 본인이 `12 - 1 = 11` 획득
4. **`mary`의 추천인은 `"-"`** → 남은 `1`원은 민호에게 가고 분배가 끝납니다.

### 1원 미만은 버리고 본인이 갖는 규칙 처리

문제의 "10%를 계산한 금액이 1원 미만이면 분배하지 않고 자신이 모두 가진다"는 규칙은 **정수 나눗셈 하나로 자연스럽게 처리됩니다.**

- `fee = money // 10`이므로 `money`가 10원 미만이면 `fee`가 자동으로 `0`이 됩니다.
- 이때 `total[curr] += money - 0`이 되어 전액을 본인이 갖고, `money`가 `0`이 되면서 `while` 조건 `money > 0`에 걸려 반복이 끝납니다.

즉 "1원 미만이면 분배하지 않는다"는 조건을 별도의 `if`로 나눠 쓸 필요 없이, 버림 나눗셈과 반복 종료 조건만으로 규칙이 그대로 지켜집니다.

### 반복 깊이가 조직도 높이만큼 깊어지지 않는 이유

`enroll`은 최대 10,000명이라 조직도가 이론적으로는 매우 깊어질 수 있지만, 실제 `while` 반복은 훨씬 빨리 끝납니다. `amount`의 최대값이 100이므로 한 판매의 최대 금액은 `100 * 100 = 10,000`원이고, 올라갈 때마다 금액이 1/10로 줄어들기 때문입니다.

`10000 → 1000 → 100 → 10 → 1 → 0`으로 **최대 5단계면 금액이 0이 되어** 조직도가 아무리 깊어도 그 위로는 올라가지 않습니다.

### 검증

문제의 입출력 예 두 개를 모두 통과했습니다.

- `[360, 958, 108, 0, 450, 18, 180, 1080]`
- `[0, 110, 378, 180, 270, 450, 0, 0]`

### 시간 및 공간 복잡도

- **시간 복잡도**: $O(N + M)$ ($N$은 `enroll`의 길이, $M$은 `seller`의 길이입니다. 판매 한 건당 올라가는 횟수가 위에서 설명한 대로 5단계 이하의 상수로 제한되기 때문입니다.)
- **공간 복잡도**: $O(N)$ (추천인 딕셔너리와 금액 딕셔너리를 판매원 수만큼 사용합니다.)
