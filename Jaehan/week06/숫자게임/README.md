# 숫자게임 문제 풀이 공유

[문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/12987)

## 1. 접근법과 단순 풀이의 한계

A팀의 출전 순서는 이미 정해져 있고 B팀만 순서를 바꿀 수 있으므로, 이 문제는 결국 **B의 카드 하나를 A의 카드 하나에 짝지어 주는 문제**입니다. A가 내는 순서 자체는 점수에 아무 영향을 주지 않기 때문에, "몇 쌍이나 B가 이기게 만들 수 있는가"만 남습니다.

- **완전 탐색의 한계**: B의 순서를 전부 만들어 보면 $N!$ 가지라, 카드가 10장만 넘어가도 계산이 끝나지 않습니다. $N$은 최대 100,000이므로 애초에 불가능합니다.
- **매번 최적 카드를 찾는 방식의 한계**: B의 카드마다 남아 있는 A의 카드를 전부 훑어서 "이길 수 있는 것 중 가장 큰 카드"를 고르면 $O(N^2)$가 되어, 10만 장에서는 100억 번 연산이 필요해 시간 초과가 납니다.
- **방향 수정**: 양쪽을 오름차순으로 **정렬해두고 포인터 하나만 앞으로 밀면서 짝을 짓는 그리디** 방식으로 접근을 전환했습니다.

## 2. 해결 코드

```python
def solution(A, B):
    ## A와 B는 각각 n장의 카드를 가지고, 매 라운드마다 한 장씩 낸다.
    ## B가 낸 카드가 A가 낸 카드보다 클 때만 B가 1점을 얻는다.
    ## A가 내는 순서는 이미 정해져 있고, B는 순서를 마음대로 정할 수 있으므로
    ## "B의 카드 하나로 A의 카드 하나를 이기게 짝지어주는" 문제로 바뀐다.
    ## 이때 이길 수 있는 A의 카드 중 가장 큰 것을 잡아야 작은 카드가 남아 뒤에서 쓰기 좋다.
    ## 양쪽을 오름차순으로 정렬해두면 이 판단을 포인터 하나로 할 수 있다.

    # 양쪽 모두 오름차순 정렬 (A가 내는 순서는 점수에 영향을 주지 않으므로 정렬해도 된다)
    A.sort()
    B.sort()

    # B가 얻은 점수
    answer = 0

    # 아직 상대해주지 않은 A의 카드 중 가장 작은 카드의 위치
    a_idx = 0

    # B의 카드를 작은 것부터 꺼내면서 A의 남은 카드 중 가장 작은 것과 비교한다.
    for b in B:

        # A의 가장 작은 카드마저 이기지 못한다면 이 카드로는 아무도 이길 수 없다.
        # 그냥 버리는 카드로 쓰고 넘어간다. (a_idx는 그대로 둔다)
        if b > A[a_idx]:

            # 이겼으므로 점수를 얻고, 상대한 A의 카드는 소진 처리한다.
            answer += 1
            a_idx += 1

    return answer
```

## 3. 구현 전략 및 이유

### 정렬 후 작은 카드끼리 맞붙이는 그리디

정렬한 상태에서 **B의 가장 작은 카드**를 **A의 남아 있는 가장 작은 카드**에 붙이는 것이 핵심입니다.

입출력 예 #1(`A = [5, 1, 3, 7]`, `B = [2, 2, 6, 8]`)로 따라가 보면 정렬 후 `A = [1, 3, 5, 7]`, `B = [2, 2, 6, 8]`이 됩니다.

1. **`b = 2`** → A의 남은 최솟값은 `1`. `2 > 1`이므로 이깁니다. 점수 1점, `a_idx`를 한 칸 옮겨 남은 최솟값이 `3`이 됩니다.
2. **`b = 2`** → A의 남은 최솟값은 `3`. `2 > 3`이 아니므로 집니다. 이 카드는 A의 가장 약한 카드조차 못 이기니 **어떤 카드에게도 이길 수 없습니다.** 그래서 그냥 버리고, `a_idx`는 옮기지 않습니다.
3. **`b = 6`** → 남은 최솟값 `3`을 이깁니다. 점수 2점, `a_idx`를 옮겨 남은 최솟값이 `5`가 됩니다.
4. **`b = 8`** → 남은 최솟값 `5`를 이깁니다. 점수 3점.

결과는 3점으로 정답과 같습니다.

### 이길 수 있는 카드 중 가장 큰 것을 잡는 이유

B의 카드로 A의 카드를 이길 수 있다면, 이길 수 있는 것 중 **가장 큰 카드**를 잡아야 손해가 없습니다. 작은 카드를 잡아 버리면 그 큰 카드는 나중에 더 큰 B 카드가 처리해야 하는데, 그 큰 B 카드는 원래 다른 카드를 이길 수 있었던 카드이기 때문입니다.

정렬 상태에서 B를 작은 것부터 처리하면 이 선택이 자동으로 이루어집니다. `A[a_idx]`보다 작거나 같은 A의 카드는 이미 앞선 B 카드들이 전부 가져간 상태이므로, 지금 `A[a_idx]`를 잡는 것이 곧 "이길 수 있는 것 중 가장 큰 것을 잡는 것"과 같아집니다.

### 진 카드에서 `a_idx`를 옮기지 않는 이유

`b <= A[a_idx]`라면 A에 남아 있는 카드는 전부 `A[a_idx]` 이상이므로, 이 `b`는 **남은 어떤 카드도 이길 수 없습니다.** 이럴 때는 A의 아무 카드에나 버리면 되고, 어떤 카드에 버리든 점수가 달라지지 않으므로 `a_idx`를 건드리지 않고 `b`만 넘깁니다. 여기서 `a_idx`를 같이 옮겨 버리면 아직 이길 수 있는 A의 카드를 헛되이 소모하게 되어 점수가 줄어듭니다.

### 검증

카드 6장 이하의 작은 입력을 무작위로 3,000번 만들어서, B의 모든 순서를 전부 시도해 본 완전 탐색 결과와 비교했고 전부 같은 답이 나왔습니다. 문제의 입출력 예 두 개(`3`, `0`)도 모두 통과했습니다.

### 시간 및 공간 복잡도

- **시간 복잡도**: $O(N \log N)$ (두 배열을 정렬하는 비용이 지배적이며, 이후 순회는 $O(N)$입니다.)
- **공간 복잡도**: $O(1)$ (주어진 배열을 제자리에서 정렬하고 포인터와 점수 변수만 추가로 사용합니다. 파이썬 정렬이 내부적으로 쓰는 공간을 포함하면 $O(N)$입니다.)
