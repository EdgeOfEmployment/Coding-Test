# 등대 문제 풀이 공유

[문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/133500)

## 1. 접근법과 단순 풀이의 한계 (처음 시도한 그리디 접근)

등대 개수 $n$이 최대 100,000까지 주어지고 뱃길이 사이클이 없는 **트리(Tree)** 형태이기 때문에, 단순한 정렬이나 주변 연결 수만 보고 판단하는 그리디적 접근으로는 전역적인 최적해를 보장할 수 없었습니다.

- **국소적 최적해의 함정**: 주변 연결 수만 보고 등대를 켜버리면, 오히려 자식 노드나 부모 노드와의 관계에서 불필요하게 켜지는 등대가 생겨 전체 개수의 최솟값을 만족하지 못했습니다.
- **방향 수정**: 트리 구조의 특성을 활용해 **가장 끝단(리프 노드)부터 거슬러 올라오며 상향식으로 판단하는 DFS(후위 순회)** 방식으로 접근을 완전히 전환했습니다.

## 2. 해결 코드

```python
import sys


def solution(n, lighthouse):
  ## 모든 등대들은 이어져있음
  ## 모든 등대들은 1개 이상의 뱃길로 이어져있으며 한 뱃길의 양쪽 끝 등대 중 적어도 하나는 켜져 있도록 해야함

  # 파이썬 재귀 깊이 제한 해제 (최대 10만 개 노드 대응)
  sys.setrecursionlimit(200000)

  # 양방향 dict(인접 리스트) 만들기
  graph = {}

  for a, b in lighthouse:
    if a not in graph:
      graph[a] = []
    if b not in graph:
      graph[b] = []

    graph[a].append(b)
    graph[b].append(a)

  # print(graph)

  answer = 0
  visited = [False] * (n + 1)

  # DFS : 'node'가 켜져 있는지 (True) 꺼져 있는지 (False)를 반환한다.
  def dfs(curr):
    nonlocal answer
    visited[curr] = True

    is_on = False  # 불이 켜져있는지
    has_off_child = False

    for nxt in graph[curr]:
      if not visited[nxt]:
        # 자식을 방문했을 때, 자식 등대가 꺼져서 돌아오면 ?
        child_on = dfs(nxt)
        if not child_on:
          has_off_child = True

    # 자식 중 꺼져 있는 등대가 있다면, 현재 등대를 무조건 켜야한다.
    if has_off_child:
      is_on = True
      answer += 1

    return is_on

  # dfs 수행
  dfs(1)

  return answer

```

## 3. 구현 전략 및 이유

### DFS 후위 순회(Post-order traversal)를 활용한 상향식 결정

트리 구조에서는 자식이 없는 가장 말단(리프 노드)부터 부모 방향으로 탐색을 완료하며 올라오는 후위 순회 방식이 필수적입니다. 자식 노드들을 먼저 모두 방문한 뒤, 그 결과를 바탕으로 현재 노드의 켜짐/꺼짐 상태를 결정합니다.

입출력 예 #1(`[[1, 2], [1, 3], [1, 4], [1, 5], [5, 6], [5, 7], [5, 8]]`)의 구조를 바탕으로 설명합니다.

1. **가장 아래쪽(리프 노드)부터 시작**

- 6, 7, 8번 같은 끝단 자식들은 더 이상 내려갈 자식이 없으므로 불을 켜지 않고(`is_on = False`), 부모인 5번 등대에게 `False`(나 꺼져 있어!)를 리턴하고 종료합니다.

2. **5번 등대의 차례**

- 5번은 자식인 6, 7, 8번을 차례대로 방문하며 `dfs`를 호출합니다.
- 이때 6, 7, 8번이 모두 `False`를 들고 돌아오는데, 이것이 바로 "자식이 꺼져서 돌아왔다"(`if not child_on:`)에 해당합니다.
- *"내 자식이 꺼져 있으니 나와 연결된 뱃길이 위험하다!"*고 판단하여 `has_off_child = True`가 됩니다.

3. **5번 등대의 결단**

- 자식들 중 꺼져 있는 애가 있으므로 5번 등대는 **자신을 반드시 켜야 합니다** (`answer += 1`). 그리고 자신의 부모인 1번 등대에게 **`True`(나 켜져 있어!)를 리턴**합니다.

4. **결과적으로 전달되는 의미**

- **자식이 `False`(꺼져 있음)를 리턴한 경우**: _"나랑 연결된 뱃길을 밝혀줄 보호막이 없으니, **내 바로 위에 있는 부모(너)가 불을 켜서 이 길을 밝혀줘!**"_ 라는 뜻입니다.
- **자식이 `True`(켜져 있음)를 리턴한 경우**: _"나는 이미 내 자식 덕분에 안전하니까, **부모인 너는 안심하고 불을 꺼도 돼!**"_ 라는 뜻이 됩니다.

- **파이썬의 기본 재귀 한도**: 파이썬은 무한 재귀로 인한 메모리 붕괴를 막기 위해 함수가 자신을 호출할 수 있는 최대 깊이를 기본적으로 **1,000번**으로 제한해 둡니다.
- **트리 구조와 재귀의 한계**: 이 문제에서 노드의 개수 $n$은 최대 **100,000개**입니다. 뱃길이 일직선 형태(외길)로 길게 이어져 있다면, DFS가 리프 노드까지 도달하기 위해 함수를 10만 번까지 깊게 호출해야 합니다.
- **해결된 이유**: 기본 설정인 1,000번을 초과하여 런타임 에러가 발생하는 것을 막기 위해, 최대 재귀 깊이를 `200,000`으로 늘려 주어 안전하게 탐색을 마칠 수 있도록 했습니다.

### 시간 및 공간 복잡도

- **시간 복잡도**: $O(N)$ (모든 노드와 뱃길을 정확히 한 번씩만 방문하므로 등대 개수 $N$에 비례합니다.)
- **공간 복잡도**: $O(N)$ (인접 리스트 그래프 저장 공간과 재귀 스택 공간을 사용합니다.)
